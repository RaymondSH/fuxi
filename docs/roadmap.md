# fuxi · 企业级知识库开发路线图

## 1. 定位

把 fuxi 从「能搜能问的知识库」升级为**会自我维护、会生产知识、可多团队隔离的企业知识中台**。
智能体策略：**先 A 后 B** —— 先把 fuxi 暴露成工具/MCP 接进企业已有 Agent（当后端/插件），
再内置 Agentic RAG（多步检索）做深度问答。

## 2. 现状基线（已交付）

鉴权（Web httpOnly Cookie、移动端 Bearer、access/refresh 撤销）· 每日 token 配额（429）·
审计与账号安全 · 按用户隔离历史 · 多空间 ACL · 独立持久化 worker · 定时备份 ·
管理后台 · 混合检索（ES+ik + pgvector + RRF）· RAG（同步 + SSE 流式）· MCP ·
知识图谱 · Wiki 编译 · 文档分块 · 本地/R2 存储 · 系统状态看板 · **v0.8.0 已上线**。

**主要缺口**：内容治理、企业连接器、监控告警、内置 Agentic RAG 与规模化能力。

## 3. 优先级定义

| 级别 | 含义 |
|------|------|
| **P0** | 安全/合规底线，对外生产前必须 |
| **P1** | 企业核心能力（含高 ROI 提质、权限地基） |
| **P2** | 成熟度（治理、接入、AI 质量、体验） |
| **P3** | 规模化与增值 |

## 5. 依赖主线

```
空间 ──→ ACL ──→ 权限感知 RAG / 角色化范围层
源文档模型 ──→ 重抓·失效检测 ──┐
独立 worker ──→ 巡检引擎(④) ──┤
①文档→Q&A ──→ 回灌检索 / 近重检测(复用 embeddings)
                              ├──→ 同源分发(⑤) ←── 通知
K-A(MCP/工具) 仅依赖现有读接口（可早做）
K-B(Agentic RAG) 宜在 ACL(M2) 之后，使多步检索天然遵守权限
K-C(自治写 agent) 必须在 审计(M0)+权限(M2)+审批 之后
```

## 6. 开发路径（里程碑）

### M0 · 安全与运维底线（P0）
- A：审计日志、账号安全（密码策略/失败锁定/自助改密找回）、JWT 加固（httpOnly+refresh，撤销可后置）
- H：入库改独立 worker（BackgroundTasks→jobs 消费，重启不丢任务）、备份/灾备、结构化日志+全局异常处理
- **验收**：可安全对外、任务不丢、操作可追溯、有备份
- **状态**：✅ 已部署并通过真库与端到端验收

### M1 · 知识精炼 + 智能体接入 A（P1，复用现有，高 ROI）
- D：①文档→Q&A/摘要 + 回灌检索；②标签治理（受控词表+归并+手改）+ 权重/权威度进排序；③角色化输出风格
- **K-A**：把 `search/qa/graph/wiki` 暴露为 MCP / 工具（带鉴权 + 配额透传），让企业已有 Agent 当后端调用
- J：笔记列表/浏览页、检索筛选；H：成本看板升级（组织总量/趋势/告警）
- **验收**：搜索/问答明显更准；外部 Agent 可经 MCP 调用 fuxi；标签/权重可治理
- **状态**：✅ 已部署并通过 MCP/检索验收

### M2 · 权限与多空间（P0 核心功能，大工程）
- B：空间(Spaces) → 文档/空间级 ACL → 权限感知检索&RAG → 细化角色（viewer/editor/空间管理员）
- **验收**：多团队内容隔离；检索/RAG/图谱/Wiki 全链路按权限过滤
- **状态**：✅ 已部署并通过跨空间隔离验收，设计见 [spaces-design.md](spaces-design.md)

### M3 · 治理巡检 + 内容生命周期 + 智能体 B（P1–P2）
- E：④巡检引擎（过期/近重/冲突/坏链/缺标签）+ 治理待办队列 + 全库冲突检测
- C：笔记编辑 + 版本历史 + 软删除；源文档模型；定时重抓/失效检测
- **K-B**：内置 Agentic RAG（问题拆解→多轮检索→引用自检），遵守 M2 的 ACL
- G：rerank（若 M1 未做）、PII/防幻觉护栏
- **验收**：知识可纠错/可回滚、能自动发现问题、复杂问答质量提升
- **状态**：✅ 已部署并通过生产端到端冒烟，设计见 [m3-design.md](m3-design.md)

### M4 · 接入与分发（P2）
- C：企业连接器（Confluence/飞书/Drive/SharePoint）
- F：订阅+通知、⑤同源变更分发、回答反馈闭环
- **K-C**：治理/精炼自治 agent 的「自动执行」（带审批 + 审计）
- **验收**：融入企业生态、知识自动同步分发
- **状态**：🚧 核心系统已部署并通过生产冒烟；真实平台连接器待凭据验收，设计见 [m4-design.md](m4-design.md)

### M5 · 规模与增值（P2–P3）
- A：SSO/LDAP/OAuth；G：评测体系；I：缓存(Redis)/多实例+LB/向量扩展；J：移动端、i18n
- **验收**：规模化、合规增值
